## 1. 서론

### 1.1 문서 목적 및 범위

본 문서의 목적은 WorkDrive 클라우드 기반 조직 협업용 파일 공유 시스템 프로젝트에 대한 테스트 기준, 테스트 범위, 테스트 케이스 설계 및 테스트 수행 결과(또는 수행 예정 상태)를 기록하는 것이다.

본 문서는 다음 내용을 포함한다.

| 구분 | 내용 |
|------|------|
| 테스트 개요 | 블랙박스 테스트 범위, 기능·비기능별 통과 기준 |
| 테스트 케이스 | 유스케이스(U_01~U_10) 및 요구사항(FR/NFR) 기반 케이스 설계 |
| 테스트 환경 | 웹 클라이언트, API 서버, DB, 파일 저장소 구성 |
| 테스트 결과 | 케이스별 수행 상태 및 종합 요약 |

**수행 상태 안내:** 본 프로젝트는 현재 요구사항 분석·설계 단계이며, 구현체가 아직 배포되지 않았다. 따라서 본 문서는 **테스트 디자인을 완료**하고, 6장 테스트 결과는 **실행 전(Not Tested, N/T)** 상태로 기록한다. 구현 완료 후 동일 케이스 ID로 재수행·갱신한다.

### 1.2 프로젝트 개요

WorkDrive는 조직 구성원이 웹 브라우저를 통해 파일을 업로드·다운로드·공유하고, RBAC 기반으로 협업 권한을 관리하는 클라우드 파일 공유 시스템이다. 파일 버전 관리, 댓글, 검색, 활동 로그(감사) 기능을 제공하여 조직 내 파일 협업 과정에서 발생하는 버전 혼선, 비인가 접근, 파일 탐색 지연 문제를 완화하는 것을 목표로 한다.

| ID | 주요 기능 | 설명 |
|----|-----------|------|
| F01 | 파일 업로드/다운로드 | 문서·이미지 등을 클라우드 저장소에 저장·조회 |
| F02 | 파일/폴더 공유 | 사용자·팀·부서·외부 링크 단위 공유 |
| F03 | 파일 댓글 | 파일 단위 협업 의견 작성·관리 |
| F04 | 접근 권한 관리 | 읽기·수정·댓글·관리자 RBAC |
| F05 | 파일 버전 관리 | 변경 이력 저장 및 이전 버전 복구 |
| F06 | 실시간 동기화 | 서버 반영 상태를 UI에 짧은 지연으로 표시 |
| F07 | 검색 | 파일명·사용자·날짜·확장자 조건 검색 |
| F08 | 활동 로그/감사 | 접근·수정·공유·댓글 이벤트 기록 |

### 1.3 용어 정의

| 용어 | 설명 |
|------|------|
| 블랙박스 테스트 | 시스템 내부 구조를 알지 못한 채 입력·출력과 동작만으로 검증하는 테스트 |
| 통과(Pass) | 예상 결과와 실제 결과가 일치하는 경우 |
| 실패(Fail) | 예상 결과와 실제 결과가 불일치하는 경우 |
| N/T (Not Tested) | 테스트 케이스는 설계되었으나 구현 미완료 등으로 아직 수행하지 않은 상태 |
| P95 | 전체 요청 중 95%가 해당 시간 이내에 처리됨을 나타내는 성능 지표 |
| RBAC | Role-Based Access Control. 역할 기반 접근 제어 |
| 공유 링크 | 외부 사용자가 특정 파일·폴더에 접근할 수 있도록 생성하는 URL |
| 감사 로그 | 파일 접근·수정·공유·댓글 등 주요 이벤트를 기록한 로그 |

## 2. 테스트 개요

### 2.1 테스트 범위

테스트는 시스템 내부 구현을 알지 못한다는 가정 하에 **블랙박스 테스트**로 수행한다. 사용자·관리자·외부 사용자 관점의 웹 UI 및 REST API를 통해 입력하고, 화면·응답·DB·로그 상태를 확인한다.

| 범위 | 내용 |
|------|------|
| Web 기반 시스템 | Ⅰ. 브라우저/서버사이드 동작 정확성 확인 Ⅱ. 요구사항(FR/NFR/IR) 충족 확인 |
| REST API | Ⅰ. 인증·파일·공유·댓글·버전·검색·로그 API 동작 확인 Ⅱ. HTTP 상태 코드·오류 메시지 정합성 확인 |
| Database | Ⅰ. 웹/API와 메타데이터·권한·로그 연동 확인 Ⅱ. 데이터 입출력·트랜잭션 정합성 확인 |
| 파일 저장소 | Ⅰ. 업로드·다운로드·버전 복구 시 바이너리 저장·조회 확인 Ⅱ. 저장 실패 시 롤백·메타데이터 불일치 방지 확인 |

**범위 외:** 모바일 네이티브 앱, 이메일 알림 연동, AI 검색 등 향후 확장 기능은 본 테스트 범위에서 제외한다.

### 2.2 테스트 항목 및 통과 기준

#### 2.2.1 기능별 테스트 항목 및 통과 기준

| 기능 | 관련 유스케이스 | 통과 기준 |
|------|-----------------|-----------|
| 회원가입 | U_01 | 유효한 이메일·비밀번호·이름만 가입에 성공하고, 중복·정책 위반 입력은 거부된다. |
| 로그인 | U_02 | 올바른 인증 정보만 로그인에 성공하고, 역할에 맞는 화면으로 이동한다. |
| 파일 업로드 | U_03 | 권한·정책을 만족하는 파일만 업로드되며, 메타데이터·활동 로그가 기록된다. |
| 파일 다운로드 | U_04 | 권한·유효 링크를 가진 사용자만 다운로드에 성공하고, 거부 시 명확한 안내가 표시된다. |
| 파일/폴더 공유 | U_05 | 공유 대상·권한(읽기/수정/댓글) 설정·변경·해제가 정확히 반영된다. |
| 파일 댓글 | U_06 | 권한 있는 사용자만 댓글 CRUD가 가능하고, 작성자만 수정·삭제할 수 있다. |
| 파일 버전 | U_07 | 버전 목록 조회 및 이전 버전 복구가 무결하게 수행된다. |
| 파일 검색 | U_08 | 접근 가능한 파일만 검색되며, 필터·정렬이 요구사항대로 동작한다. |
| 활동 로그 | U_09 | 주요 이벤트가 필수 필드와 함께 로그에 기록된다. |
| 관리자 기능 | U_10 | 관리자만 사용자·정책·로그 관리 화면에 접근·변경할 수 있다. |

#### 2.2.2 비기능별 테스트 항목 및 통과 기준

| 항목 | 관련 요구사항 | 통과 기준 |
|------|---------------|-----------|
| 브라우저 호환 | NFR-001, NFR-002 | Chrome, Edge, Firefox 최신 버전에서 핵심 기능이 정상 동작한다. |
| 성능(검색) | NFR-005 | 파일명 검색 P95 응답 시간 2초 이내 |
| 성능(다운로드) | NFR-006 | 다운로드 스트림 시작(TTFB) P95 3초 이내 |
| 성능(댓글) | NFR-007 | 댓글 목록 조회 P95 2초 이내 |
| 보안(인증) | NFR-009, FR-003 | 비로그인 사용자는 주요 기능 URL/API 접근이 차단된다. |
| 보안(권한) | NFR-010, FR-018 | 권한 없는 파일 접근·다운로드·댓글 작성이 100% 차단된다. |
| 보안(외부 링크) | NFR-013, FR-014 | 만료된 공유 링크 접근이 거부되고 만료 안내가 표시된다. |
| 신뢰성(업로드) | NFR-015, NFR-017 | 정상 환경에서 업로드 성공률 99.9% 이상, 저장 실패 시 기존 데이터가 손상되지 않는다. |
| 사용성 | NFR-019~NFR-021 | 주요 작업 평균 5클릭 이내, 오류 상황 시 명확한 안내 메시지 제공 |

## 3. 테스트 케이스

### 3.1 테스트 케이스 선정

테스트 케이스는 본문 2.2의 기능·비기능 테스트 항목과 요구사항 분석서의 유스케이스(U_01~U_10) 및 예외 흐름을 기준으로 선정하였다. 블랙박스 테스트 기법을 적용하여 사용자·관리자·외부 사용자 시점에서 입력·동작·출력을 검증한다. 각 케이스는 요구사항 ID와 추적 가능하도록 `관련 요구사항` 열을 포함한다.

### 3.2 테스트 케이스 유형

| 유형 | 설명 | 예시 |
|------|------|------|
| 입력 검증 | 필수값·형식·정책 위반 입력에 대한 시스템 반응 확인 | 회원가입 이메일 형식, 비밀번호 정책 |
| 동작 확인 | 정상 흐름에서 기능이 요구사항대로 수행되는지 확인 | 파일 업로드 후 목록 표시 |
| 권한·보안 | RBAC, 세션, 공유 링크 만료 등 접근 제어 확인 | 비권한 사용자 다운로드 차단 |
| 연동 확인 | 웹 UI ↔ API ↔ DB ↔ 저장소 간 데이터 일관성 확인 | 업로드 후 DB 메타데이터·바이너리 일치 |
| 성능 | 응답 시간·처리량 등 비기능 목표 충족 확인 | 검색 P95 2초 이내 |
| 호환성 | 브라우저·OS 환경별 UI·기능 동작 확인 | Chrome/Edge/Firefox 동일 동작 |

### 3.3 테스트 케이스 목록

#### 3.3.1 회원가입 기능 테스트 케이스 (U_01)

| T2 | user@test.com | Passw0rd! | 김철수 | FAIL — 중복 이메일 안내 | FR-001 |
| T3 | invalid-email | Passw0rd! | 홍길동 | FAIL — 이메일 형식 오류 | FR-001 |
| T4 | user2@test.com | 1234 | 홍길동 | FAIL — 비밀번호 정책 미충족 | FR-001, NFR-011 |

#### 3.3.3 파일 업로드 기능 테스트 케이스 (U_03)

#### 3.3.4 파일 다운로드 기능 테스트 케이스 (U_04)

사전 조건: T10 업로드 파일 `report.pdf` 존재, 공유·링크 설정 가능.

| Case | 조건 | 예상 결과 | 관련 요구사항 |
|------|------|-----------|---------------|

## 5. 테스트 환경

### 5.1 테스트 환경 구성

본 프로젝트는 구현 전 단계이므로, 아래는 **계획된 테스트 환경**이다. 구현 후 동일 구성으로 STaging 환경을 구축한다.

```
[테스터 PC] ──HTTPS──▶ [Web Browser (Chrome/Edge/Firefox)]
                              │
                              ▼
                    [WorkDrive Web UI / REST API Server]
                         │              │
                         ▼              ▼
                  [Database]    [File Storage (Object/Blob)]
                         │
                         ▼
                  [Activity Log / Audit Store]
```

| 구분 | 항목 | 계획 사양 |
|------|------|-----------|
| 클라이언트 | OS | Windows 10/11, macOS (선택) |
| 클라이언트 | 브라우저 | Chrome, Edge, Firefox 최신 stable |
| 서버 | API/Web | Node.js 또는 Spring Boot 기반 (구현 시 확정) |
| 데이터 | DB | PostgreSQL 또는 MySQL (메타데이터·권한·로그) |
| 저장소 | File Storage | 로컬/S3 호환 객체 저장소 |
| 네트워크 | 프로토콜 | HTTPS (TLS 1.2+) |
| 테스트 데이터 | 시드 | user@test.com, userB@test.com, admin@test.com, 샘플 PDF/이미지 |

| 테스트 도구(계획) | 용도 |
|-------------------|------|
| Postman / curl | API 블랙박스 테스트 |
| Chrome DevTools | 네트워크·성능(P95) 측정 |
| 브라우저 수동 테스트 | UI·권한·오류 메시지 확인 |
